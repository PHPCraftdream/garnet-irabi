# Временные фазы брони: что читает время и кто на него реагирует

Карта для инструмента сдвига времени. Она отвечает на один вопрос: если
подвинуть `start_at`/`end_at` слота, что именно изменится в поведении
системы и где это станет видно.

Всё время в системе — unix-секунды в колонках слота. **Единственный
источник «сейчас»** — `time()` в PHP и `UNIX_TIMESTAMP()` в SQL; ни одна
из проверок ниже не хранит собственных часов. Поэтому сдвиг данных
эквивалентен сдвигу часов, но затрагивает только те строки, которые
подвинули.

## Фазы жизни занятия

Границы заданы отношением `start_at` и `end_at` к «сейчас». Между
соседними фазами меняется и то, что человек видит, и то, что делает крон.

| Фаза | Условие | Что становится правдой |
|---|---|---|
| Далёкое будущее | `start_at > now + 24ч` | слот в каталоге, бронируется, напоминаний ещё не было |
| Сутки до | `now + 2ч < start_at ≤ now + 24ч` | окно суточного напоминания |
| Два часа до | `now < start_at ≤ now + 2ч` | окно двухчасового напоминания; суточное уже не отправят |
| Идёт | `start_at ≤ now < end_at` | из каталога пропал, забронировать нельзя, подтверждённую бронь отменить нельзя |
| Прошло | `end_at ≤ now` | крон завершает слот и брони, неподтверждённые брони отменяются с возвратом |

## Кто читает время

### Проверки на запись (отказывают человеку)

- **Создание слота** — `ExpertSlotsService::createSlot`: `start_at < time()`
  отвергается. Пересечение ищется по `[start_at, end_at)` того же
  преподавателя (`ExpertHelpers::findOverlap`).
- **Редактирование слота** — там же: перенос в прошлое отвергается,
  пересечение проверяется с исключением самого слота.
- **Бронирование** — `SlotsController::post__book` и `post__bookData`:
  `start_at <= now` → отказ `slot_in_past`.
- **Отмена брони** — `BookingsController`: подтверждённую бронь нельзя
  отменить, когда `start_at <= now`. Неподтверждённую — можно и после,
  потому что преподаватель её так и не подтвердил, и деньги надо вернуть.

### Выборки на чтение (меняют то, что видно)

- **Каталог** — `SlotsController::get__main`: `start_at > UNIX_TIMESTAMP()`
  и `start_at < now + 4 недели`. Слот исчезает из каталога ровно в момент
  начала — на этом основан открытый дефект D-034.
- **Главная** — `MainController`: ближайшие брони фильтруются
  `start_at >= now`.
- **Список броней** — `BookingsController`: по умолчанию бронь скрывается,
  как только её слот прошёл (`start_at >= now`); прошедшие показываются
  только по явному переключателю. То есть после сдвига слота в прошлое
  бронь исчезнет из списка по умолчанию — это ожидаемо, а не потеря.

### Крон (действует сам, без человека)

- **`booking-reminders`** — `CronReminderService::sendDue`. Два окна,
  каждое со своим потолком и полом:

  | Срок | Окно отправки | Колонка отметки |
  |---|---|---|
  | за сутки | `now + 2ч < start_at ≤ now + 24ч` | ученику `bookings.reminded_1d_at`, преподавателю `time_slots.reminded_1d_at` |
  | за два часа | `now < start_at ≤ now + 2ч` | ученику `bookings.reminded_2h_at`, преподавателю `time_slots.reminded_2h_at` |

  Нижняя граница у суточного не декоративная: если крон не отработал
  вовремя, суточное письмо не уйдёт за десять минут до занятия — оно
  выглядело бы поломкой. Отметка ставится **до** отправки: письмо идёт в
  очередь со своими повторами, и продублировать поставленное в очередь
  хуже, чем изредка потерять одно напоминание.

- **`complete-expired`** — `CronCompletionService::completeExpired`, по
  `end_at < now`, три независимых прохода:
  1. слот `booked` → `completed`, его брони `confirmed` → `completed`;
  2. слот, оставшийся `free` (групповой недобрал), — его подтверждённые
     брони всё равно завершаются;
  3. брони `pending` на прошедшем слоте отменяются, деньги возвращаются.

## Что из этого следует для сдвига

Сдвигать надо **и `start_at`, и `end_at`** одной дельтой: они читаются
разными проверками, и рассинхрон даст занятие, которое уже началось, но
никогда не заканчивается.

**Отметки напоминаний надо сбрасывать вместе со сдвигом.** Иначе слот,
однажды прошедший окно, при возврате в будущее останется помеченным и
второго напоминания не пришлёт — сдвиг будет выглядеть неработающим,
хотя дело в отметке.

**Сдвиг сам по себе ничего не отправит.** Все письма идут из крона, а
крон ходит по расписанию хоста. Поэтому инструмент обязан дёргать
`booking-reminders` и `complete-expired` сразу после сдвига — иначе
эффект придётся ждать до следующего запуска.

**Порядок фаз при движении назад во времени не обратим.** Завершённую
бронь возврат слота в будущее не расколдует: `complete-expired`
переписал статусы, а обратного перехода нет. Проверять фазы надо от
дальней к ближней, а не наоборот.

## Границы инструмента

Двигаются только строки, принадлежащие аккаунтам на `irabi-uat.test`.
Слот живого преподавателя не должен сдвинуться никогда: это его
расписание и деньги его учеников. Проверка — по `expert_id` слота и по
`user_id` брони, а не по тому, кто запросил сдвиг.
